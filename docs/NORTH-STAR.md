# North Star

## Project purpose

Give the user a dependable AI development partner that turns a clear design envelope into tested software while preserving intent, evidence, and control across sessions.

## Invariants

- the user chooses the destination and consequential business or technical forks.
- the agent owns routine, reversible implementation decisions and proves them through verification.
- Project purpose is stable; implementation routes may change when evidence invalidates an assumption.
- Current truth must be concise and reloadable. Historical decisions remain traceable without masquerading as current instructions.
- The harness source, canonical project source, and optional deployment target are distinct locations.
- Money, providers, architecture, destructive actions, merges, and releases require the user's approval.

## Success condition

After an interruption or context compaction, an agent can reconstruct the goal, current state, active task, accepted decisions, evidence, and next action from the repository before changing code.
